System Architecture

How articles flow from user submission through moderation to the public leaderboard — and how the dataset grows over time.

Components
Cache Layer
Two-tier: in-memory dict for hot paths, then database lookup. Same URL analyzed twice costs nothing on the second call.
Rate Limiter
5 fresh analyses per IP per 24h. 100 total per day globally. Enforced in the database — survives restarts. Cached results bypass this entirely.
Claude Sonnet
Scores each article across 5 structural dimensions. Returns a full JSON response including outlet name, claims, cross-source coverage, and missing context.
DB · pending
Every fresh analysis is stored immediately with status=pending. PostgreSQL in production; SQLite for local development. Outlet and region extracted from Claude's response.
Moderation Queue
Admin reviews pending articles: canonicalises the outlet name, confirms the region tag, checks scope and plausibility. Approve or reject with one click.
/admin UI
Simple protected interface showing the pending queue. Authentication via Bearer token (ADMIN_TOKEN env var). No database access for reviewers — everything goes through the API.
DB · approved
The leaderboard source of truth. Only approved articles with a canonical outlet name and region tag appear here. Seed articles land here directly on startup.
pramaana_data.py
Version-controlled seed dataset. Human-reviewed founding articles that auto-populate the database on every fresh deployment. The project's auditable starting point.
Outlet Leaderboard
Live leaderboard averaging scores across all approved articles per outlet, broken down by dimension. Grows automatically as articles are approved.
dataset/articles.json
Periodic export of all approved articles. Portable, citable, usable independently of this codebase. The dataset as a public good — for researchers, journalists, and forks.
